# Univer生命周期异常修复与验收

日期：2026-10-29。对应整改清单第53节。

结论：已稳定复现并修复`SheetsScrollRenderController2`未注册异常，完成反复开关、预览切换、撤销重做、保存重开和VTable回归。该项记为**H3-OBS01-A，已修复并验收**。第30.4节另有一条历史`Cannot read properties of null (reading 'row')`，本轮未复现，原始过程堆栈此前已清理，不能证明与本次异常同源；拆分为**H3-OBS01-B，历史观察**，不以本轮零异常将其认定为已修复。

本次没有增加旧配置迁移、兼容分支或双写，没有改用Univer展示正式报表。

## 1. 复现与根因

实际入口为测试项目中“[预设四] 车间交付与质量交叉报表”的模式三配置弹窗。打开后，在原生名称框刚出现时立即输入`C4`并回车，再关闭配置：修复前连续6轮均出现依赖未注册异常；另一次阶段探针也捕获同类错误，合计保留7条堆栈。先操作工具栏、撤销或预览再关闭的10轮普通流程没有异常，解释了之前“偶发”的表现。

本地安装的Univer **1.1.0**源码和运行探针共同确认：

| 时机 | SDK行为 | 原项目行为及风险 |
| --- | --- | --- |
| `Ready = 1` | 工具栏和名称框已出现 | 项目立即发布API和`onReady`，用户可以操作名称框 |
| 名称框跳转 | 派发`sheet.command.scroll-to-cell`，直接解析滚动控制器 | 若仍处于Ready阶段，解析`SheetsScrollRenderController2`失败 |
| `Rendered = 2` | SheetsUI插件注册滚动渲染控制器 | 应以此作为项目编辑器可交互的边界 |
| 关闭配置 | React卸载，SDK销毁延后到微任务 | 旧公式等待、预览和保存任务仍可能在关闭后继续，必须先取消所属会话 |

核查位置：`@univerjs/core`的`LifecycleService.onStage`、`@univerjs/sheets-ui`的`ScrollToCellCommand`及SheetsUI插件`onRendered`。本次依据已安装依赖源码修正调用，没有通过固定延时猜测编辑器是否完成初始化。

同时发现公式等待API使用错误：`onCalculationResultApplied(timeout?: number)`接受超时数值，不能传入回调注册监听。正确接口是返回可释放订阅的`calculationResultApplied(callback)`。

## 2. 修复内容

### 2.1 初始化和命令边界

`src/univer/adapter.ts`等待真实`LifecycleStages.Rendered`后才将实例标记为ready。`UniverPreview`在此之前保留可测量的容器尺寸，将原生界面设为不可见且`inert`，显示“正在初始化报表编辑器…”。只有就绪的当前实例才能公开API、绑定业务事件、发出`onReady`及显示画布。

关闭自动抢焦点；在Rendered之前拒绝需要滚动渲染控制器的跳转命令，关闭后拒绝该实例的所有命令。没有把全部操作延迟到更晚的Steady阶段；真实格式刷在阶段2发起、阶段3完成的路径已验证。

没有传入快照或网格时，创建显式25行×15列空白工作表，避免无工作簿导致一直无法到达Rendered。

### 2.2 会话取消和销毁

新增`src/univer/lifecycle.ts`，由每个实例自己的`EditorSession`管理`starting → ready → closing → disposed`状态和AbortSignal。

- 卸载先同步关闭会话，立即取消等待，清空当前实例对应的公开引用；旧实例的迟到回调不能覆盖下一次打开的实例。
- 业务事件解绑后，仍在微任务中执行SDK销毁，保留React18 StrictMode下避免嵌套root同步卸载的处理。
- 释放、关闭和历史桥接清理均可重复调用；已关闭API保留弱引用标记，不再进入已销毁的依赖注入器。
- 只将本项目定义的`EditorSessionClosedError`作为正常关闭处理。活跃实例的真实初始化、公式订阅或切换错误仍上报，不按错误文本批量吞掉SDK异常。

### 2.3 公式、预览和保存

公式结果通知、300ms有界等待和会话关闭共用一条清理路径：取消定时器、移除abort监听、释放SDK订阅；同步回调、迟到回调和重复关闭也只清理一次。该超时是结果等待的上限，不用于判定SDK初始化完成，也不宣称所有计算在300ms内必定完成。

预览切换和保存各自捕获当前会话与编辑器句柄，异步结束后再次校验所属实例；关闭后不再编译旧画布、更新模式或回写保存结果。预览切换增加同步互斥，旧请求的finally也不能更新下一轮状态。历史桥接拒绝在实例关闭后同步撤销栈。

测试项目`HybridReportEditModal`增加保存请求代次校验。验收中确认AntD的`confirmLoading`会阻止`onCancel`，使等待中的“取消”看似可用但实际无效；改用确认按钮自身的`okButtonProps.loading`，保留防重复保存，同时允许取消立即使旧请求失效。

### 2.4 依赖约定

组件库的Univer peer最低版本以及本地开发依赖、测试项目依赖声明对齐到1.1.0。本次验收前后实际解析的已有包版本无变化，SDK没有升级；声明变化是为了准确表达已经使用并验证的API要求。锁文件同步更新。
