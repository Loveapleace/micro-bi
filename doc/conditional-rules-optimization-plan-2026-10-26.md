# 条件规则、多条件与最终显示文本替换优化方案

日期：2026-10-26。对应清单第37节。状态：**已实施并验收**，详见[实施及验收记录](conditional-rules-implementation-and-acceptance-2026-10-26.md)。本文保留设计契约，下一表为实施前基线。

2026-10-27约定补充：旧条件字段不校验、不执行、不迁移，不因其存在阻断预览或保存。仅检查新模型自身有效性，详见[修正及回归](ignore-legacy-conditional-fields-2026-10-27.md)。

前提按用户修正：**现有告警条件有效，且新方案不需要兼容旧配置**。本方案围绕多条规则、单条规则的AND/OR组合及命中后替换显示文本展开，继续提供数值告警、样式、计算与VTable展示能力；条件配置统一采用新模型，不做历史格式迁移、回读、双写或旧规则语义还原。

## 1. 推荐方案

把“动态阈值告警”升级为共用的“条件规则”管理器，仍从原单元格高级设置进入。每条规则由作用目标、条件组、命中动作和执行顺序组成；命中动作可同时设置样式、替换显示文本。条件求值与动作合成由一个纯TS模块负责，Univer与VTable使用相同结果。

核心约束：**值、基础格式化文本、条件后的最终文本分别保存。** 例如数值600可以显示为“低产”，计算和数值排序继续使用600。规则作用于源格/业务身份及其展开实例，不保存这一次展开的D3:D15坐标。

本次范围包括明细、分组、双向交叉透视、已有静态格与范围跟随说明；普通样式和条件命中样式均支持“仅单元格 / 整行”，并共用文字色、背景色的自定义调色盘。保留原面板与单元格驱动入口。新增能力不要求展示端使用Univer。真实数值替换仍属于已有人工覆盖/业务计算能力，不能由“替换显示文本”暗中触发。

## 2. 当前能力与改动依据

| 位置 | 实施前行为 | 优化要求 |
| --- | --- | --- |
| `CellAdvancedSettings.tsx` | 读existingRules[0]，保存时重新组装一个规则数组 | 改为完整的新模型草稿，支持增删、复制、排序、启停及稳定ID；未声明字段按新schema校验 |
| 现有条件UI | 一个比较符、1～2个数值阈值、一个样式方案 | 条件树支持AND/OR；增加文本/空值比较、字段/指标引用及文本替换动作 |
| 普通样式和颜色UI | 直接配置单格样式，颜色为预设标签及十六进制输入框 | 增加统一的单元格/整行范围，文字/背景共用可视化调色盘及规范化颜色值 |
| `ConditionalRule` | 数值比较与style，没有文本动作、enabled或停止标记；targetCellId由运行时as any附加 | 定义完整类型、目标约束和动作，不继续叠加未声明字段 |
| `cellExpansionEngine.ts` | 支持全局及单格条件、按数值求值、合成样式 | 复用共享求值器，扩展类型与动作；准确处理region、角色及命中解释 |
| `expandTemplate.ts` | 有另一套数值判断，主要消费全局规则 | 各展开入口统一调用新规则求值器，移除各自的旧条件判断分支 |
| `BiGridCell`/`PublishedCell` | 已分别有value/v及displayText | 沿用数值与显示文本分离，增加明确的展示来源标记，避免空文本被当未设置 |
| `gridAdapter.ts` | 优先把displayText映射到VTable records | 继续使用最终显示文本；原值排序/导出从publication.v取值 |
| `buildBiGrid.ts`、`UniverPreview.tsx` | 部分高级格式会把格式化文本写入工作簿v；数值格式又可能影响最终绘字 | 条件文本使用独立呈现投影，保证数值/公式不变；初次装载与增量刷新一致 |

截图示例的“交付件数＜90”对应原13条数据的300～1500，因而0命中。只读编译实验中，“＜1000”在中性发布及VTable适配均有9条标红，支持“原条件有效”的修正。[实验记录](verification/conditional-rules-plan-2026-10-26/current-engine-probe.json)仅是编译/适配检查，没有额外宣称本轮做了浏览器全量渲染验收。

样式回显要求：当前代码绿色预设保存色为`#389e0d`，回显判断却使用`#52c41a`。新模型用明确的presetId和同一份样式常量完成读写，自定义样式按新定义保存；不通过旧颜色组合猜测或转换预设。这与“告警条件是否有效”是两个问题。

## 3. 配置交互设计

### 3.1 保留原入口

原单元格高级设置中增加“条件规则”页；“父格与上下文”独立成页，避免父格选项挤占规则编辑空间。明细字段、聚合指标、公式、维度文字和静态格均可进入；按类型提供可用操作，而不是只对measure开放。

页面分为规则列表、当前规则编辑、试算结果三部分。规则列表提供添加、复制、删除、启停、上移/下移或拖拽；修改后仍通过原OK及保存报表链路提交。

### 3.2 一条规则包含什么

| 配置 | 设计 |
| --- | --- |
| 名称和启用 | 如“低交付预警”；禁用保留原条件/动作，启用后恢复 |
| 作用目标 | 默认当前源格的全部展开实例；可显式选同指标/区域范围。显示目标名称和身份，不以最终坐标绑定 |
| 触发角色范围 | 默认业务数据格；总计、小计、表头、维度标签分别显式勾选，决定哪些格可以触发条件。整行样式的接收范围由样式动作单独确定 |
| 比较依据 | 默认有效数值；可选显示尺度数值或基础格式化文本。阈值旁显示单位和实际样本 |
| 条件组 | “全部满足AND / 任意满足OR”，支持添加条件及子组；支持NOT时用显式非/不等/不包含操作 |
| 条件来源 | 本格；明细同一记录字段；分组/透视同一事实交集中的已计算指标 |
| 命中动作 | 设置样式、替换显示文本可分别勾选，也可同时执行 |
| 样式作用范围 | 仅单元格（默认）/整行；普通“样式与排版”与条件动作均提供，影响范围说明随报表结构实时更新 |
| 自定义颜色 | 文字色、背景色均有调色盘，支持可视化选色、HEX/RGB、预设及最近使用色；整行与单格使用同一颜色数据 |
| 执行顺序 | 列表从上向下执行；显示“命中后停止”，新规则默认开启 |
| 未命中行为 | 默认保留基础格式化显示；可为规则集显式设置默认显示动作 |

字段引用遵循业务上下文。明细的“良品率”读取同一记录；分组/透视读取当前行列切片里的对应指标。聚合格引用一个多值原始字段时，必须明确聚合方式或改选已计算指标，不能任取第一条，也不能读取旁边某个绝对坐标。

### 3.3 样式与文本动作

样式保留现有红/橙/绿预设，并可设置文字、背景、加粗、对齐等已有属性。不能因选择预设而清掉无关的原字号、边框或换行。

### 3.3.1 样式作用范围

在普通“样式与排版”和条件规则的“设置样式”动作中，共用“仅单元格 / 整行”单选项，默认仅单元格。选项决定每个目标实例的视觉影响范围，目标实例集合仍由原源格或条件匹配决定；模板格的普通样式作用于其全部展开实例，条件样式只由命中的实例触发。

| 范围 | 行为 |
| --- | --- |
| 仅单元格 | 只改变目标展开格的视觉属性；目标为合并单元格时，以该合并对象整体显示，不拆合并 |
| 整行 | 按当前展开格所在的实际网格行，覆盖目标报表区域从行标签到末尾业务列的范围；包含该行指标标签、动态叶列以及开启的末尾行总计列，冻结/隐藏列也属于逻辑范围 |

“整行”在明细中是一条记录所在行；在分组或指标纵排透视中是当前指标所在的物理行。普通数据行命中不会自动修改同组其他指标行、独立标题/表头行、小计行或其他报表区域。若触发格本身是跨行合并对象，则以其占用的明确行带为范围，界面直接显示将影响几行。

列范围来自目标region的运行时业务footprint，随透视列和总计开关变化重算，不使用工作表预留列数、当前视口宽度或远处自由备注的最右位置。多区域共存时只处理所属区域；纯静态格没有可定位的区域时，选择整行需补充静态区域/列范围。

整行只扩展样式，数字格式、单位、缩放、公式、父格、聚合和文本替换仍遵守各自的原目标。比如交付600触发整行红底，订单号、车间与其他数值格可以着色，只有命中的交付格显示“低产”，不会把整行文字都改成“低产”。

合并格边界规则：同一行的横向合并格可整体接收样式；跨行合并格仅在其全部行都被同一最终样式覆盖时整体着色。只命中其中部分行，或各行最终样式不同，则该跨行合并格保留原样式，试算标注未覆盖原因。不得只修改合并主格而把一行的告警扩大到其他行，也不为着色自动取消合并。

### 3.3.2 自定义颜色调色盘

新增共用颜色编辑组件，在普通样式和条件样式中复用。可采用当前已安装AntD ColorPicker；本地类型提供单色、预设、HEX/RGB格式、清除和变化完成回调，无需为此替换UI库。

- **选色方式**：色相条、饱和度/亮度面板、HEX/RGB输入及颜色预览；首版用单色模式与不透明色，背景另有“无填充”动作。
- **颜色入口**：文字颜色和背景填充分别配置；预设色与自定义色在单格、整行中都可使用。
- **保存格式**：统一为规范的`#RRGGBB`字符串，三位HEX及RGB输入转换到同一表示。组件颜色对象不进入源模板。非法HEX/RGB在草稿中提示，不提交无效色值。
- **预设回显**：用户改动预设中的颜色后标记为自定义，保留其他未改属性；不在重开时根据相似颜色重新猜测并覆盖用户选择。
- **最近使用**：高级设置确认时记录最多12个去重色值，作为编辑器偏好共用；不复制到每条规则，也不因更新偏好单独产生报表历史。
- **清除含义**：区分“不覆盖此属性”“恢复基础色”和“无填充（仅背景）”。清除调色盘选择表示不覆盖；显式重置/无填充有独立标记，不能都保存成空字符串。
- **草稿与历史**：拖动选色只更新草稿及节流预览，点击高级设置OK时原子提交一次，取消则恢复。一次拖动不产生几十条撤销记录。

切换单元格/整行范围保留同一条样式记录的颜色与其他属性，只更新作用范围，不同时遗留两份cell/row样式。字体或换行导致的行高变化由统一布局处理，显式行高/列宽规则不被颜色操作改写。

### 3.3.3 文本动作

文本动作提供：

- 固定文本：`低产`、`达标`、`异常`。
- 文本模板：`低产（{formatted}）`、`{fieldLabel}：{value}`。
- 显式空文本：命中后隐藏文字，但保留真实数值与命中状态。

首版固定占位符为`{value}`有效原值、`{formatted}`基础格式化文本、`{fieldLabel}`字段/指标名称；已具备上下文时提供`{rowLabel}`、`{columnLabel}`。通过按钮插入占位符，未知占位符在保存前提示，模板按纯文本解释。

替换发生在基础格式化之后，不再自动给“低产”追加“件”或把它执行一次数字格式。需要单位时使用已经含单位的`{formatted}`。空字符串是有效替换结果，undefined才代表沿用原显示。

### 3.4 示例

以下阈值只用来展示配置能力，业务阈值由用户确定：

| 执行顺序 | 条件 | 样式 | 最终文字 | 原13条数据的数量 |
| --- | --- | --- | --- | --- |
| 1 | 交付件数＜700 | 红字浅红底 | 低产 | 5 |
| 2 | 交付件数≥700 AND 交付件数＜1000 | 橙字浅黄底 | 关注 | 4 |
| 3 | 交付件数≥1000 | 绿字浅绿底 | 正常 | 4 |

数值600显示“低产”，1200显示“正常”。原数值、SUM结果和数值排序不变。用户可把第二条改为“交付件数＜700 OR 良品率＜90”，前提是良品率引用有明确的同记录/同切片口径。

### 3.5 试算与解释

辅助面板显示匹配格、最终触发格、受影响行/单元格及跳过的跨行合并格数，并展示选中格的原值、基础格式化文本、条件真假、最终文本及样式来源。以4列明细中5条记录命中为例：仅单元格影响5格；整行影响5行/20格，文本仍只替换5个命中格。同一行多个命中格不重复计行数。

合法但0命中允许保存；提示“当前数据无匹配，样本600＜90为false”。语法、类型、目标歧义等错误阻止提交错误的新规则。暂时移除的指标使规则休眠并提示，不删除配置。

## 4. 统一规则模型与执行语义

### 4.1 唯一源存储

统一采用`document.presentationRules`作为唯一条件配置入口，新结构首版标识为version=1。规则集包含稳定id、全局order、目标、规则数组、默认动作及revision；每条规则包含稳定id、name、enabled、组内order、predicate、actions和stopIfTrue。全局order用于不同规则集的行样式冲突裁定，不随列遍历顺序变化。无规则使用明确的空规则数组。

删除旧`document.conditionalRules`、单格顶层/content.conditionRules的条件配置读写与求值入口，不添加迁移器、兼容适配或双写。旧字段直接忽略，不检查其存在与内容，不触发错误或保存屏障。类型、面板、编译器、保存接口、示例和测试夹具使用新结构；version只校验显式提供的新presentationRules，不分发旧版本解析器。未提供新模型时按无规则处理。

| 模型部分 | 最低要求 |
| --- | --- |
| 目标 | sheetId、regionId、源格/指标身份、角色范围，必要时加完整成员选择器 |
| 条件 | 类型化树：AND/OR组、比较叶节点，左右操作数声明来源及类型 |
| 操作符 | 数值gt/gte/lt/lte/eq/ne/between；文本相等/包含/前后缀；集合in/notIn；空值判断 |
| 动作 | 样式动作声明scope=cell/row及stylePatch；文本动作仍绑定命中格，二者作用目标分开解析 |
| 普通样式 | document.styleRules保存同结构的视觉样式动作和作用范围，生成默认样式仍可作为基础；条件规则只存presentationRules，不把普通样式伪装为永真条件 |
| 颜色 | 规范HEX色、显式reset及背景none操作有明确类型；未声明字段表示不覆盖，不使用空字符串承载多种含义 |
| 运行时结果 | 原值保持，输出resolvedStyle、displayText、displaySource及可选命中来源 |
| 诊断 | 无效引用、类型不符、条件无匹配、被前序规则拦截等区分 |

目标解析使用区域和语义身份，不能仅凭相同fieldKey把不同区域/聚合口径混为一个目标。新配置在面板结构切换时按语义身份重新定位；无法唯一匹配则保留休眠/待重绑规则。这是新规则运行期间的稳定性要求，不属于旧格式兼容。

### 4.2 一致的执行规则

1. 先完成现有数据展开、聚合、公式与合法实例覆盖，得到有效值；生成基础格式化文本。
2. 每条条件读取同一份不可变值/文本上下文。前一条的“低产”不能变成后一条的比较输入。
3. 按列表顺序处理已启用规则；命中后执行动作，stopIfTrue为true时停止处理该格后续规则。
4. 显式继续匹配时，同一作用层的后续动作按属性覆盖前面的动作；界面明确提示“后续动作可覆盖本规则”。没有指定的属性继续继承；跨范围的最终层级见下述样式合成规则。
5. 没有规则命中时使用原基础显示；仅命中样式动作时，文本仍是原格式化文本。
6. 最终呈现从基础层重新合成。取消规则、阈值变化或数据不再命中时，要恢复原文本和原样式，不能在前次告警样式上持续叠加。

数值比较不隐式把null、空串或空白字符串转成0。零值即使显示为空，仍不等于原值为空。数值字符串、布尔及日期按字段类型和显式转换处理，避免Number字符串转换带来意外命中。

按“显示尺度数值”比较时，只使用明确的scale/百分比变换，不从`¥1,200.00万元`之类的文本parseFloat。界面同时给出原值和显示尺度值，阈值单位明确。

样式按“主题/生成基础→普通整行→普通单格→条件整行→条件单格”合成。单格条件样式可覆盖已生效的整行条件样式；该优先级只处理已经通过条件及停止判断的动作，不能绕过stopIfTrue执行被拦截的规则。

同一行的不同指标/透视列可能同时产生行样式。冲突按规则管理器的稳定全局顺序（ruleSet.order、rule.order、稳定ID）解决，不按列遍历顺序决定。相同规则对同一目标行重复命中时，行样式动作去重；文本动作保留每个命中格各自的结果。

### 4.3 引擎接线

新增共享的新模型校验、目标解析、条件求值、动作合成与命中统计模块。当前明细、分组、交叉透视的所有展开入口及纯静态/辅助工作表都调用同一纯TS求值器。接线时替换原条件求值代码，不保留双模型分支；编译发布层不能再重复执行一次规则。

增加共用的样式目标解析阶段：先求值并确定触发实例，再解析cell/row目标、去重、处理合并边界，最后逐目标格合成resolvedStyle。普通样式使用同一目标解析和合成逻辑。行目标由源身份、完整行路径与当前布局解析，保存时不固化当前行号或结束列；运行时行号只用于本次投影。

Univer预览目前直接消费展开器的grid，因此只修改compileCellReport会造成预览与展示不同。应在各grid完成值计算及最终实例布局后调用共享规则阶段，再返回给预览和发布。

静态范围说明应在最终实例生成后取得owner及行列分组上下文。不能只在负行号临时样本上求涉及父组的条件，否则每组不同文字无法正确计算。

## 5. Univer呈现与VTable消费

### 5.1 保留Univer原值和公式

不能直接把工作簿的数值v=600改成字符串“低产”，否则原生公式引用、筛选及排序可能读取到文字；即使源编译器仍保留600，也会出现两套计算语义。

建议建立`ConditionalDisplayPlugin`作为呈现适配层：

1. 中性grid保留value及formula，另给出最终displayText和明确的条件呈现来源。
2. 工作簿保留原数值/公式；UI渲染拦截返回用于绘字的文本，或使用自定义文字绘制及默认字形跳过标记，不把文案写进存储v。
3. 当前安装SDK已提供registerCellCustomRender、registerSheetMainExtension及fontRenderExtension.isSkip等接口。实施第一步先验证默认文字抑制、换行、合并、缩放、选区及重绘，接口存在不代表全链路已完成。
4. 数值的固定文本可评估使用原生自定义数字格式字面量作为优化；需验证正/负/零、特殊字符及未命中恢复。不能将该方案直接泛化为任意字符串/布尔/空值的完整实现。
5. 若选定方案不能同时保证原值不变、文字正确和原生公式正确，则PoC不通过，不能以修改v的方式绕过。

本阶段的关键PoC：600显示“低产”，公式`该格+1`仍计算601；替换为空文本时也能算601。规则取消后恢复600的原数字格式，工作簿save中的v/f均未被文案污染。

### 5.2 初始装载、增量刷新与保存

`buildBiGrid.ts`和`UniverPreview.tsx`的装载/刷新必须采用相同显示策略。对前次渲染的条件颜色、背景、格式和显示标记计算清理差异，防止再次变成正常值后仍显示红色或“低产”。

`syncWorkbookToTemplate.ts`、`BiBindingManager`和混合设计器快照同步需要区分程序派生显示与真实用户编辑：没有编辑的条件文字、临时格式或告警颜色不得被保存为源文字、基础样式或人工实例覆盖。

显示层若用了临时数字格式，同样不能把该格式固化成用户原格式。条件规则保存后仍按新数据重新求值，不能保存某一次低产结果代替规则。

### 5.3 VTable、合并与复制

VTable继续读取publication中的displayText和已解析样式，publication.v保留数值；展示端不运行另一套条件表达式。

整行样式在中性模型中展开为每个目标格的resolvedStyle，两端按同一结果绘制，不各自推断行范围。字体常规/非斜体、恢复基础色、无填充等清除操作需映射为明确重置；VTable适配不能只处理bold=true而漏掉false。未完整覆盖的跨行合并格保持其原主格样式，完整覆盖且一致时只更新一次合并对象。

默认沿用现有按类型值合并及完整组边界。600和650都显示“低产”时，不因此自动合并；更不能把两个同名但身份不同的业务组合并。规则变更也不能清除已有取消合并记录。

复制转换区分“显示内容”和“原始值”口径：显示内容得到低产，原始值从publication.v得到600。按2026-10-27最新要求，展示态及编辑态均不显示这两个复制按钮或顶部占位条；原表格基础能力不变，本轮不扩展复制功能。复制产品方案后续另行设计，既有转换函数保留。

数值排序/筛选从原值或有效值执行，不能直接对VTable中“低产/正常”字符串排序而声称仍按交付量排序。原生搜索若暂保留查原值，应在说明中明确；完整xlsx条件规则转换作为独立导出能力评估，不在本方案中承诺所有表达式可无损转换。

## 6. 新配置保存、历史与生效

- 新配置只读写presentationRules；统一按列表执行，新建规则stopIfTrue=true，用户显式继续匹配时才设为false。不保留旧priority还原或其他历史执行模式。
- 编辑、启停、排序和重存不重新生成全部ID；禁用保留完整条件和动作。整个规则集一次提交，重复ID或非法字段按新schema明确报错。
- `HybridCellDesigner`将新规则作为可变源状态纳入当前模板、Ref及HybridHistory，不持续从initialDocument覆盖当前草稿。
- `preserveHybridDocumentMetadata`、`hybridTemplateState`、designerReducer及retainedCells统一传递新结构。新报表中的样式、备注、公式、父格和范围跟随规则正常协同。
- 普通styleRules及条件样式的scope、颜色、显式重置与无填充都纳入源保存及HybridHistory。样式范围切换更新同一记录，禁用/撤销后重新合成受影响格并清理前次行样式。
- 新规则的revision参与templateRevision及发布缓存失效判断。仅改规则、数据不变也重新发布；数据更新后按新值匹配。旧规则结果缓存不能作为新模型的有效结果复用。
- 设计端、编译器和宿主按同一个新契约发布，重建项目示例和自动化夹具；历史条件如需继续使用，按新界面重新配置，不自动迁移。
- 取消旧配置兼容不会取消新配置的保存重开、撤销重做、指标暂时移除后的规则休眠，以及数据/布局变化后的语义定位。
