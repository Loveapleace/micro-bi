## 1. 结论与实施范围

下钻技术上可行，现有源格身份、展开树、事实切片和中性发布模型可以复用。主要工作是把准确的业务范围从展开阶段传到点击事件，并管理查询结果、临时Sheet、保存和会话生命周期。

用户补充的“双击聚合值，新建明细Sheet”适合首期：保留主报表布局，用独立页签查看对应事实。它属于汇总值追溯明细，与在主表中改变行列分析粒度分开实施。

| 阶段 | 建议交付 | 复杂度与影响 |
| --- | --- | --- |
| A：明细与跳转 | 双击指标打开临时明细Sheet；菜单支持查看明细、参数化目标报表；分组及双向交叉共用上下文 | 中等；需贯通配置、编译、发布、宿主查询、双端Sheet及保存隔离，但不改变主表分析结构 |
| B：逐级分析 | 行或列独立钻入、上钻及面包屑；另一轴及全局筛选保持 | 较高；增加运行时分析计划，涉及聚合、布局、样式、合并和坐标公式的重定位 |
| C：局部展开 | 某车间展开下级、某月份展开日期，其他分支保持原层级 | 高；需分支级展开状态、动态原型尺寸、小计、行列交叉和分页策略，不宜与A捆绑上线 |

首期采用**主表保持、结果Sheet临时只读、同范围复用页签**。大数据按页加载，不一次将所有事实转换为Sheet单元格。抽屉/弹窗可以保留为后续展示容器选项，不作为首期必要的第二套交互实现。

## 3. 双击新建明细Sheet的双端设计

### 3.1 与Univer示例的关系

Univer官方说明支持在透视表值区域双击查看明细；FPivotTable.drillDown通过命令创建包含相关源记录的工作表，属于`@univerjs-pro/sheets-pivot`。当前项目没有该透视表插件，报表由自己的编译器展开成普通工作表，再交给VTable展示，不能直接对现有格子调用原生透视表的drillDown。

建议复用这一交互形式，由项目自己的业务范围解析器查询事实。现有Univer基础Facade已声明insertSheet、setActiveSheet及deleteSheet，可用于预览侧承载结果；不要求首期安装透视表插件或替换聚合引擎。

参考：[Univer透视表](https://docs.univer.ai/zh-CN/guides/sheets/features/pivot-table)、[FPivotTable.drillDown](https://docs.univer.ai/ko-KR/reference/facade/pivot-table)、[FWorkbook工作表API](https://docs.univer.ai/reference/facade/workbook)。线上最新SDK能力仅作参考，实施时以本地已安装1.1.0的实际行为验收。

### 3.2 用户操作

| 场景 | 双击行为 |
| --- | --- |
| 模板设计态 | 保留现有行为：空白/生成文字原生编辑，业务格高级配置；不自动打开明细 |
| 动态预览主Sheet | 已配置明细动作的业务格双击打开临时明细Sheet；原生编辑保持禁止 |
| 正式VTable主Sheet | 已配置明细动作的业务格双击打开临时明细页签；仍由VTable显示，零Univer展示运行时依赖 |
| 临时明细Sheet | 只读，首期不支持递归双击下钻；允许切回主Sheet、关闭及翻页 |
| 无动作/不支持范围 | 保留选择和复制，不能静默改为查询全表 |

单击继续选择单元格，双击只触发一次查询；右键菜单提供同一动作，解决双击不易发现及多动作选择。多个动作时可以指定一个默认双击动作，其余通过菜单触发。交互提示使用独立图标/光标，不覆盖条件规则已有颜色和文案。

明细Sheet显示来源范围、指标口径、数据版本、加载/空结果/错误状态、明细列和分页。页签可命名为“A车间·2026-08·交付明细”，内部身份不依赖名称；同一来源、动作、范围、数据版本重复打开复用已存在页签。关闭后返回来源Sheet并恢复选区、滚动和冻结状态。临时页签数量及缓存有上限，具体上限在实际数据量下确定。

### 3.3 保存及生命周期隔离

临时结果由独立DrillSession/RuntimeSheetStore管理，不加入CellTemplateDocument.sheets/cells/regions，也不回写已保存cellBundle.publication。展示时组合基础publication与runtimeSheets；序列化时仅保存基础模板、基础publication及动作规则。

预览侧在原Univer实例中创建临时Sheet，需登记运行时拥有的sheetId。所有快照同步、protectGuidedSnapshot、getTemplate、保存包生成及editorSnapshot导出都必须排除这些Sheet；仅靠隐藏页签或Sheet名称前缀不足以隔离。保存时activeSheet若为临时Sheet，应映射回合法源Sheet，不能保存失效的活动ID。

需为运行时控制器提供会话内、限定sheetId的内部创建/填充/删除事务，保持普通预览命令只读；这些程序操作不进入用户源历史。切回设计态先关闭临时Sheet并恢复主表；关闭设计器、取消请求或会话过期后，迟到响应不得插入新Sheet。清理不能删除同名的用户工作表。

## 4. 共用技术链路与数据契约

建议链路：

```text
interactionRules（源格动作）
  → 展开时生成typed scope / lineage（事实范围）
  → 完成布局、动态合并与范围跟随后生成发布交互索引
  → Univer/VTable事件命中同一动作解析器
  → 本地事实适配器或宿主查询回调
  → 临时明细Sheet / 宿主报表跳转
```

以下名称均为拟议契约，不是现有API：

- **InteractionRule**：规则ID、源sheet/region/cell、预期字段和角色、动作列表、默认动作。与presentationRules分开，启停或删除动作不影响条件、样式和合并。字段暂时取消时规则休眠，重选按原身份恢复；改名保持，换为另一字段不能沿坐标继承。
- **ScopeDescriptor**：datasetId、regionId、完整行列成员约束、区域/宿主筛选、时间桶语义或区间、记录主键条件、聚合口径、数据快照标识。成员值保留原始类型；同字段在不同轴或不同粒度出现时，使用轴/源维度身份区分。
- **PublishedInteractionIndex**：去重动作表、范围表、交互实例索引及合并命中信息。坐标仅用于命中当前发布结果，业务执行依赖源格、实例和scopeId。只为启用动作的实例生成条目，不逐格附带事实或全部重复筛选。
- **DrillRequest**：来源报表/Sheet/实例、动作、scope、原事实值/有效覆盖值、页大小、游标或页码及排序。打开目标报表时按显式映射生成业务参数；不能用条件替换文字取代原始业务键。
- **宿主回调**：例如queryDrillDetails(request,{signal})及openDrillReport(request)。请求地址、鉴权、服务端权限及跨数据源映射由宿主实现，源JSON不保存函数或SQL。服务端仍校验实际访问范围，前端scope只提供查询条件。

### 4.1 业务范围与时间

分组数据格范围为全局/区域筛选与完整行路径的交集；交叉数据格再加入完整列路径。维度成员格表示该成员在当前有效筛选下的全部范围。小计只移除被汇总层级的约束，保留其上级及另一轴；总计不生成“字段=总计”条件。

保留现有区域筛选语义；成员匹配则与实际展开分组使用同一类型编码逻辑，不能把区域筛选的宽松eq直接用于成员定位。list明细优先按稳定记录主键查询。无主键的重复明细不能用某个显示字段冒充唯一记录。

标准时间桶在统一时区/日历语义下形成[start,end)范围，周起始日、自定义天数及边界一致。无时间、无效时间是不同的成员。自定义format如果把不同年份或多个桶映射为同一组，实际分组可能不是一个连续区间，须保留真实桶谓词/区间并集；不能凭“8月”标签猜成某年的一个月份。宿主不支持某范围时返回明确的不支持状态，禁止退化成无时间限制的查询。

### 4.2 合并与公式

动态group-span的维度合并按源成员范围查询。相邻同值或人工合并要检查合并前各格的scope、指标与动作是否等价；只有等价才统一触发。跨不同业务范围的合并首期禁用直接明细并说明原因，后续再考虑范围选择；不能以左上角代表全范围。取消合并不移除动作，解除后各格恢复自己的命中关系。

SUM/AVG/COUNT/MIN/MAX按实际参与计算的事实及空值口径追溯。同切片业务公式可显示其原始字段及计算说明；人工覆盖显示原事实值和覆盖值，明细仍来自原事实。

任意sheet-formula可能引用其他车间、月份、Sheet或人工值，不能假设当前行列路径就是其全部来源。首期仅对能证明单一事实范围的公式开放自动明细；其余显示不可自动追溯，或由显式目标报表动作处理。后续“查看计算来源”应实现公式依赖解析，不把多范围简单并集后宣称其汇总等于公式值。

### 4.3 数据刷新、并发和性能

请求使用真实数据快照、模板/规则版本及当前会话校验。主表刷新后原请求失效；已打开明细应标记过期，按新的同语义实例重新加载或明确提示来源已不存在。服务端不能读取指定历史版本时，应说明返回的是最新明细，不能承诺与旧汇总对账。

同范围请求去重，连续点击采用请求序号和AbortSignal双重控制。缓存键包含来源/目标数据源、范围、数据版本、宿主运行范围、明细列、排序及分页，有容量限制。关闭页签即释放监听和未完成任务。

编译时不对每个格子复制事实列表；沿用现有节点/切片的运行期引用生成小型scope，发布后不携带ruleFacts。点击先查索引，不扫描整张报表；本地适配器首次过滤可能为O(N)，按快照缓存可复用结果。远端按页查询，Sheet只装载当前页，并说明“当前页/总数”，不能把分页结果标成完整明细。打开明细不重跑主表聚合，翻页不重建Univer实例。切换VTable页签可以更新可见表实例，但需缓存主表模型及每个Sheet的浏览状态。

| D-CTX-06 | 全表总计 | id[1..8]；再加区域/宿主筛选后仅返回筛选内事实 |
| D-CTX-07 | 多级行列及两条时间轴 | 完整父链、实际时间字段与轴身份不丢；不能选到同字段的错误分桶定义 |
| D-CTX-08 | F2类型成员与同名标签 | 数字1和字符串“1”分别命中原事实；null、空串、false、0不互串 |
| D-CTX-09 | F3列表身份 | 按主键定位；无唯一身份时不伪造单条事实，重复主键有诊断 |
| D-CTX-10 | F4时间桶 | 边界[start,end)、周起始日、时区、自定义format实际组范围与聚合一致 |
| D-CTX-11 | 空交叉、无时间及无效时间 | 空切片显示0条；特殊成员按真实分组处理，不去掉条件查全表 |
| D-CTX-12 | 目标报表与跨数据源 | 业务键、类型和参数映射正确；缺失必需映射时不打开未筛选目标 |

### 6.4 分阶段浏览器验收

阶段A从真实模式三入口创建分组和交叉各一份报表，配置动作并保存重开；预览与正式展示各双击验证精确id、指标、上下文和临时Sheet。至少走一轮：配置→预览开明细→切回设计→保存→重开→正式开明细→翻页→关闭返回→数据变化→再次打开。原始模板除用户实际动作编辑外保持不变，统计执行请求数、活动监听数和临时Sheet数。

阶段B另测行钻入保留列、列钻入保留行、同时限定行列后的再次钻入、多步返回；保存模板不携带浏览状态。阶段C再测仅A展开而B收起、仅8月展开而9月收起、两轴局部展开交叉、小计不重复计入总计、叶子禁止继续展开、分支新增/删除及返回恢复。阶段A通过不能宣称B/C通过。

### 6.5 性能与发布门槛

| 测试 | 记录与门槛 |
| --- | --- |
| 10万事实、5万发布格基线 | 对比无动作和启用部分动作的编译耗时、publication字节数、堆内存和首屏；索引只包含动作实例，不序列化每格事实列表 |
| 单次明细与重复打开 | 记录范围命中、查询、第一页转换及首屏P50/P95；同范围同版本复用查询及页签，不重新编译主表 |
| 远端分页 | 大结果只加载当前页；验证请求页大小、排序、取消和错误；正文注明是否完整，不出现全量Sheet填充 |
| 压力与清理 | 连续20轮开关明细和10轮开关设计器，确认无重复请求放大、迟到回写或持续内存增长；关闭后活动监听/请求/临时Sheet归零 |

耗时上限和可接受的索引体积增量须在实际宿主设备/数据量测得基线后设定，不以未经测量的固定毫秒数承诺。功能发布要求范围id集合、版本和保存隔离全部正确，并完成`npm test`、组件库ESM/CJS/声明构建、宿主生产构建及真实浏览器验收。纯数据入口在Node可导入，展示入口不新增Univer依赖。提交复验数据、来源指纹、浏览器记录及性能原始结果；本轮只读探针不代替这些检查。
