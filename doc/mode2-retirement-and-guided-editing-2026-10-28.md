# 模式二下线与模式三受控编辑：实施及验收

日期：2026-10-28。按用户决定取消模式二，不兼容、迁移或反推模式二报表配置。产品仅保留模式一图表分析与模式三表格报表；模式编号沿用现有名称。

## 1. 产品与读取边界

| 入口 | 配置源 | 展示 |
| --- | --- | --- |
| 模式一 | `ChartConfigV1`；分类、系列、指标、筛选和图形样式 | VChart |
| 模式三 | 面板生成数据区的模板；Univer编辑外观、静态内容及合并意图 | VTable消费重新编译的publication |
| 模式二 | 创建、编辑、示例、转入入口及自由设计器公共导出均删除 | 不读取旧条目，不提供转换 |

宿主只接受`authoringMode='chart'`且新图表结构有效的条目，或`authoringMode='hybrid'`且包含明确模式三源描述的条目。模式三要求`documentType='cell-template'`、`schemaVersion='2.0'`、`capabilitiesVersion='cell-expansion-v2'`、工作表和单一数据区域；新源采用`hybridConfig.version=2`及行列轴描述。项目已声明的模式三`hybridConfig v1 + showRowTotals`继续复用现有读取路径，不因模式二下线误丢模式三来源；不接受没有Hybrid标识的自由模板。

`isGuidedSourceDocument`是产品读取边界，后续仍由现有模板校验器检查有效配置。不会根据自由模板的位置或字段猜测面板。旧模式二条目即使带有发布结果也被忽略；混合列表中的有效图表和模式三条目继续保留。若持久化列表没有任何可用条目，展示当前四个预设。保存采用现有存储键，仅持久化当前有效列表。

`HybridCellDesigner`收到不受支持的源时不会反向初始化自由布局，预览及保存给出源结构错误。旧条件字段的处理仍遵循第39节：直接忽略，不校验、不执行、不迁移。

库删除`CellReportDesigner`、`CellInspector`、`ReportWizardModal`及独立`designerReducer`，并从`micro-bi/cell-designer`移除对应导出。`AuthoringMode`仅保留`chart | hybrid`。

宿主删除`CellReportEditModal`、自由模式示例工厂、模式二预设及状态/保存分支；移除菜单中的模式二和两个自由设计示例，以及模式三转自由设计器的回调。另移除两个引用已不存在TSX源文件的独立验收HTML入口。

保留模式三实际依赖的共享展开器、父格执行模型、稳定身份、公式、条件规则、范围跟随、合并与取消例外、快照同步、源历史和发布编译器。保留这些底层能力不表示仍支持模式二的产品配置。现有纯引擎示例和有效编译回归继续使用。

本次不实施模式二与模式三往返转换，也不创建新的专家入口。新增报表形态应在模式三增加受控配置、生成适配和对应验收。

## 3. 模式三允许怎样编辑

| 对象或操作 | 当前行为 |
| --- | --- |
| 字段、时间轴、多级分类和指标 | 通过左侧面板修改，生成数据区结构并重新展开 |
| 数据区表头、维度、指标及内部空白 | 禁止直接输入、F2改值、覆盖公式、粘贴、剪切和清空内容 |
| 数据区字体、颜色、数字格式、备注说明及条件规则 | 模板设计态继续配置；规则按源身份保存 |
| 父格与扩展方向 | 高级设置只读；度量保留合法聚合设置，明细列表不能用来替换生成的度量结构 |
| 标题及数据区外静态格 | 可输入文本和工作表公式，可配置范围跟随、样式与原生静态合并 |
| 原型内部插行、插列、删除字段行列或移动数据块 | 阻止，避免面板与画布产生不同结构 |
| 整个数据块之前或之后的安全行列插入 | 保留已有整体平移；静态区域编辑继续支持源撤销重做 |
| 工作表新增、删除、复制、改名、隐藏、重排及直接截断尺寸 | 不作为本轮受控编辑能力开放 |
| 动态预览 | 数据、文本和样式只读；允许既有合并/取消合并意图操作 |

保护范围根据当前面板生成的原型矩形计算，包含原型中的空白间隔；不把标题行号固定为第一行或第二行。双击数据源格继续打开高级设置；双击原型内部无绑定空白不会创建新的自由数据格。

原生快照在采集时再次恢复数据区原值和公式，保留样式、静态备注和既有元数据。已有静态范围配置在只读属性保存时保持原样，避免修改格式时顺带删除规则。

## 4. 合并、公式和命令保护

保护接入SDK公开的`BeforeSheetEditStart`、`BeforeClipboardPaste`和`BeforeCommandExecute`，并在源历史监听之前注册。程序投影及源历史回放使用既有事务标记放行。被取消的输入不启动新的源历史记录。

检查实际命令范围及`cellValue`绝对坐标；多格粘贴即使从静态区开始，只要跨入数据区也会阻止。剪贴板文本和HTML用于提前估算覆盖范围，快照同步作为最终源保护。

本次实际浏览器检查发现并修正三个容易误伤的SDK行为：

1. 字体和颜色也通过`set-range-values`提交，但参数为纯样式`cellValue`。设计态放行纯样式补丁；带内容或公式的混合补丁仍受保护。
2. 取消合并会提交样式补丁，合并还会清空被覆盖格。对SDK明确的合并命令链，数据区仅接受几何和样式，剥离清空内容的补丁；静态设计区沿用原生Excel行为。数据区不弹出与实际行为不符的“丢弃其他值”确认。
3. 原生公式异步回写结果发生在投影事务结束之后。仅放行带`sourceFormulaData`身份且只写`v/t`的结果补丁，仍由SDK校验原公式身份；不能借此替换公式、富文本或样式。

实际合并600和750后，两格底层值均保留；原生`SUM(C4:D4)`仍为1350。合并范围进入源意图，正式VTable继续读取计算后的publication，不依赖Univer实例。

## 5. 模板、预览、保存重开和展示链路

左侧配置→`compilePanelToCellTemplate`→模式三源状态及保留元数据→原型/动态网格→Univer投影。设计编辑只回收允许的静态内容、外观和合并意图；保存前刷新快照和公式状态，再由`compileCellReport`发布。

保存包继续包含源模板、publication和版本戳。重开按`hybridConfig`恢复左侧面板及源规则；事实数据变化时重新编译源模板，VTable消费新publication。工作簿快照和某次预览坐标不成为另一份权威配置。

样式、条件和合并沿用既有身份校验。字段临时取消或切换数据角色时，原规则可以休眠保留；不能把明细列的规则直接套给同名汇总指标。恢复原身份后再生效。

取消分组合并保存为成员上下文例外。人工合并保存主格和覆盖实例的语义身份；成员删除时规则休眠，恢复后重新定位。取消合并不删除其他样式、条件或备注。
