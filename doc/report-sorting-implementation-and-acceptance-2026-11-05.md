# 报表排序交互、实现及验收（2026-11-05）

## 1. 交付范围

模式三采用已确认的“表头快捷操作＋统一排序设置”。模板设计与动态预览使用 Univer，正式展示继续使用 VTable。设计器保存默认规则，展示图元保存自己的查询排序，两者使用同一套规则、设置面板和计算逻辑。

| 表格 | 排序对象 | 规则与移动单位 |
| --- | --- | --- |
| 明细表 | 原始记录 | 支持多条件优先级；整条记录移动 |
| 分组表 | 某一级维度成员 | 在同一父级内按名称或聚合指标排序；整组移动 |
| 交叉表 | 行、列各级维度成员 | 两轴独立；按成员值或指定交叉范围的指标排序；整个行块、列块移动 |

左侧“指标拖拽”负责报表布局中的指标排列。此处的“数据排序”负责运行时记录/成员顺序，不改变指标排列。普通格式、样式、条件文本和下钻继续使用既有配置。

## 2. 交互入口

### 2.1 表头快捷菜单

- 仅真实生成的维度表头、列维度成员及指标标签显示排序入口。标题、自定义静态文字、数值结果格没有排序按钮。
- 维度菜单提供升序、降序、排序设置及恢复该项默认顺序。时间维度使用“时间从早到晚/从晚到早”。
- 指标标签菜单提供“从小到大/从大到小”，自动带入指标和当前另一轴的完整成员路径。
- 点击交叉表列成员，可选择“按本列指标排序…”，带入该列的取值范围；可在设置中换指标、排序层级。
- 菜单显示排序对象和作用范围。例如“同一区域内的车间”，明确一次操作影响的成员。
- 只点击图标才打开菜单，单元格选择、内容编辑和双击下钻沿用原行为。
- 已排序入口显示方向；明细表的多条件还显示优先级序号。统一入口旁显示当前规则摘要。

### 2.2 排序设置

| 内容 | 明细表 | 分组/交叉表 |
| --- | --- | --- |
| 排序对象 | 字段 | “行：车间”“列：月份”等具体层级 |
| 排序依据 | 该字段的实际值 | 成员名称/时间先后，或已有指标及其聚合口径 |
| 顺序 | 升序、降序 | 升序、降序 |
| 取值范围 | 不出现 | 按指标排序且有另一轴时出现，支持全部汇总或完整路径切片 |
| 优先级 | “首先按/然后按”；手柄拖拽，键盘上下键也可调整 | 根据维度层级执行；各层级各一条规则 |
| 新增/删除 | 多条件，禁止重复目标 | 可配置多个层级及两轴，禁止重复目标 |

修改设置只影响草稿，“应用”后计算，“取消”丢弃草稿。设置页中有缺失字段、失配指标或失配维度路径时标红，修正后才能应用；参考成员仅暂时没有数据时，允许保留规则。

展示态“恢复默认”删除实例排序覆盖，恢复模板默认排序，并保留筛选、隐藏列等查询条件。逐项恢复只恢复对应目标。设计器的恢复操作清空自定义默认规则。

控件使用现有 AntD 组件和宿主隔离前缀，弹窗内下拉列表挂载到弹窗内容容器，保持正确的层叠关系和指针响应。VTable 使用公开 `getIcons()` 返回的内置排序图标及 `icon_click` 事件，业务菜单与设置复用共用组件。

## 3. 排序规则与计算顺序

1. 从宿主获取完整事实，执行当前时间范围和事实筛选。
2. 明细表按多条件稳定排序记录，然后展开；相同条件有主键时按主键稳定比较，否则保持输入顺序。
3. 分组/交叉表构建成员树，在各父级内比较兄弟成员。父级换序时子树整体移动。
4. 名称按自然数字及中文排序比较；时间按事实中的实际时间比较，不按格式化显示字符串比较。自定义 `MM/YYYY` 也能跨年正确排序。
5. 指标排序从该成员事实与另一轴切片的交集中，使用指标原有求和、平均、计数、最小、最大或业务公式计算分数。聚合复用结果单元格的同一个求值函数。
6. 空值与无交集结果在升、降序中均置后。零正常参与比较；同分成员使用稳定的成员键顺序。
7. 根据排好的树重新计算几何位置、工作表相对公式、条件显示、合并与下钻索引。
8. 编译完成后才做显示列投影和分页。Excel 导出使用完整的筛选后排序结果。

排序不会把汇总表拆成独立物理行排序，也不依赖条件替换后的“告警”等文字、千分位或百分号进行比较。改变排序不改变数据范围、指标聚合口径或总计数值。小计与总计仍由模板的层级和位置生成。

按 A1 坐标计算的工作表公式继续随实例重新计算，但不作为首期排序依据，避免“排序影响坐标、坐标又决定排序”的依赖循环。可选计算指标为与事实绑定的业务公式。

## 4. 身份与保存

源模板增加 `defaultSortRules`，实例 `ReportQuery` 增加 `sortRules`。

```ts
interface ReportSortRule {
  targetId: string;
  order: 'asc' | 'desc';
  by: 'value' | 'metric';
  metricId?: string;
  slice?: { targetId: string; memberKey: string }[];
}
```

- `targetId` 由工作表、区域、轴、源格、字段、时间分桶配置和完整父级链生成，行列使用同一个字段时仍区分身份。
- `metricId` 包含源指标、字段及聚合方式；业务公式还包含表达式、作用域及计算精度。
- 切片保存完整路径及带类型的成员键，区分数字 `1`、文本 `"1"`、空串和 `null`。时间切片保存与展开引擎一致的桶成员身份。
- 不保存 A1 坐标、列号或显示文案作为规则身份。表头改名、样式变化、数据重排不改变规则目标。
- `query.sortRules === undefined` 继承模板默认排序；`[]` 表示明确清空实例排序；非空数组替换默认规则。
- webEditor 的查询校验保留合法规则和暂时失配的语义引用，完整序列化后按原工程/页面/图元/报表唯一键写入 localStorage。
- 本次不读取或迁移旧表格单字段 `sort` 配置；模式一图表仍使用自己的排序配置。

## 5. 动态数据与结构变化

| 变化 | 行为 |
| --- | --- |
| 新增/删除记录、改变记录输入顺序 | 保留规则，在新事实集上重新比较 |
| 新增车间、月份或多级列成员 | 按当前规则自动参与排序 |
| 删除作为依据的月份/成员 | 暂停该条规则，显示明确提示，原配置保留；成员恢复后自动重用 |
| 原参考成员不变，仅显示名变化 | 规则保持有效 |
| 数据源暂时为空 | 保留规则，展示空数据；事实恢复后重新生效 |
| 更换字段、父级层级、时间粒度 | 身份失配，提示重新选排序对象/范围；不猜测替换 |
| 更改排序指标聚合口径或业务表达式 | 原指标规则失配，提示重新选择 |
| 取消合并后排序/改变数据 | 合并规则及取消意图保持；重新计算坐标 |
| 多图元使用同一个报表 | 默认规则共享；各自的查询覆盖独立保存 |

## 6. 渲染与生命周期

- VTable 的 records 是工作表行，保持 `showHeader: false`。由发布模型提供 `sortHeaders` 与 `sortCatalog`，不启用矩阵记录的内置业务排序。
- `ReportTableRuntime` 的列回调读取最新网格，图标状态随数据刷新；数据、列宽、合并或排序变化继续复用原生实例。
- `projectReportSheet` 同步重映射表头操作坐标，合并主格被隐藏/分页裁掉时携带主格操作。
- Univer 设计格携带 `sourceCellId`；表头按钮使用公开 `getCellRect()` 和可见范围 API 定位，只为当前视口中的表头创建控件。滚动、缩放、选区和尺寸事件通过 RAF 合并更新，卸载时释放事件、观察器和 RAF。
- 源历史事务包含默认排序，撤销/重做还原规则。应用排序前采集当前编辑，旧画布不可回采覆盖新排序事务。
- 指标汇总分数、切片成员编码、时间比较键在本次计算内缓存；没有高频定时全表扫描。

## 9. 复验方法

1. 在 micro-bi 运行 `npm run build`、`npm run test:only`，并运行 `node node_modules/typescript/bin/tsc -p embedded/tsconfig.json --noEmit`。
2. 在 webEditor 运行 `npm run prepare:micro-bi`，启动实际编辑器开发服务。
3. 配置 `PLAYWRIGHT_MODULE`、`CHROME_PATH`、`MICRO_BI_HOST_URL` 后运行 `node scripts/verify-micro-bi-report-sort.cjs`。
4. 可用 `MICRO_BI_SORT_KIND=pivot|grouped|detail` 单独检查，`MICRO_BI_SORT_OUTPUT` 保存 JSON，`MICRO_BI_SORT_SCREENSHOT_DIR` 保存三类截图。`MICRO_BI_SDK_ASSET_DIR` 可将 SDK 资产路由到新构建的本地目录。
5. 重开浏览器页面以加载新 SDK 模块，再进入配置面板或展示预览。
