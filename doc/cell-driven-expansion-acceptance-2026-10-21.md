## 4. 继续整改清单

### CER-F01：主应用新建和保存协议没有切到新能力

**P1。CER-03失败。**

`dynamic-data-test/src/components/CellReportEditModal.tsx:35`的真实createDefaultCellTemplate仍返回schemaVersion=1.0、capabilitiesVersion=cell-v1，并写入grouped/columns。因此普通“使用单元格设计新建”继续走旧表型，而不是默认进入v2。设计器只对识别为2.0的输入隐藏两个控件，不能弥补主入口仍建旧模板。

同文件第158行保存包schemaVersion也固定1.0；即使外部提供v2模板，包能力声明也未同步。该保存包问题为源码确认，未冒充浏览器提交反例。

整改步骤：

1. 新建factory产生显式2.0/cell-expansion-v2模板，不写全局layoutKind/metricDirection；示例提供明确新旧入口或完成可审查转换，不让旧示例名称冒充新模式。
2. 保存包按真实模板能力选择协议，并校验reader、模板和publication兼容性。禁止1.0包静默携带必须按2.0解释的能力。
3. 保留旧模板兼容路由，但新建默认入口与旧模板重开分开；补原应用点击→配置→保存→刷新重开证据。

关闭标准：真实新建入口不显示全局表型/指标方向，源包确为新能力，保存后VTable生效并可正确重开；仅修改标签或隐藏按钮不算通过。

### CER-F02：v2实例键与快照保存不同，覆盖值保存后失效且冲突缺失

**P1。CER-04/05失败。**

事实A=10，在实际展开网格中编辑为999，经syncDocumentFromWorkbookSnapshot和JSON保存后生成1条覆盖，但新引擎重新展开仍为10。新引擎将内部类型化成员key再次编码进instanceKey；数据绑定的semantic.rowPath也携带了与标签路径不同的值形式，快照同步器再按其语义字段另造键。双方没有使用同一规范身份。

另一用例直接使用引擎原键构造有效覆盖，可命中999；源事实10改15后仍无CONFLICT诊断。`cellExpansionEngine.ts:815`附近只按键找第一个绑定并赋值，没有沿用旧引擎的不可变事实基线、失效归档和完整状态处理。

整改步骤：

1. 由公共codec输出规范业务身份与唯一instanceKey，标签、度量、保存同步器共用；绑定显式携带templateCellId、regionId、原事实基线及完整类型化路径。
2. 保存器优先使用已校验绑定身份，禁止根据metricId/当前坐标重建另一套键；同一度量在两个模板格出现时也能准确区分。
3. 统一active/conflict/orphaned生命周期；基线比较在应用覆盖前执行，成员消失产生持久可解释诊断，不静默丢覆盖或把上一人工值当事实。
4. 加入10→999→1000、JSON保存重开、源10→15、成员删除/回归和模板局部重排回归。

关闭标准：CER-04/05通过，目标格及非目标格均准确；保存实际编辑后VTable仍为999/1000，源未变无冲突，源变才有真实冲突。

### CER-F03：既有公式在新引擎静默发布空值

**P1。CER-06/07失败。**

现有业务语法`IF([SUM(qty)] > 0, [SUM(defects)] / [SUM(qty)], 0)`在qty=10、defects=1时应为0.1，实际publication值为null且valid=true。`evaluateDataCell`只替换简单`[field]`后使用JavaScript Function求值，未复用已有IF/SUM等表达式执行链；catch后直接null。

工作表公式`=1+1`同样发布null且有效，新引擎没有对应sheet-formula执行分支。不能把“未崩溃”当作公式正确。

整改步骤：复用项目既有公式解析/求值及明确作用域，不另定义一个只能运行简单JS表达式的隐式语言；支持的公式正确执行，暂不支持的语法/引用/函数给出错误并阻断发布。保存源公式，避免降级literal。补当前车间示例的完整比例与总计、工作表引用、除零和未知公式回归。

关闭标准：CER-06结果0.1，CER-07结果2或明确不支持错误；不能valid=true却静默清空指标。

### CER-F04：时间分桶配置在v2没有实际执行

**P1。CER-08失败。**

日期格声明timeBucket.day，同一天08:00和17:00、qty=10/20应为一组30，实际拆成10和20两行。buildRowNodes/buildColNodes直接按原字段值encodeMemberValue分组，没有消费timeBucket。

整改步骤：使用共享时间桶执行器，先按配置的时区、周起始、粒度生成类型化成员键，再枚举排序；保留原事实用于聚合与下级过滤。桶定义参与schema身份，格式化显示不替代实际分组。

关闭标准：行/列两个方向的日/月/周及跨边界用例均通过；改变粒度有明确迁移/例外失配诊断，不丢保存规则。

### CER-F05：明细键使用显示字段，没有稳定主键保护

**P1。CER-09/10失败。**

两条记录id分别a/b、显示字段均same，新引擎为两个quantity实例生成相同业务键；重复id=same的明细仍编译valid=true。列表节点路径目前来自被展示字段值，而不是记录主键，只有“显示字段本身恰好唯一”的旧测试能掩盖问题。

整改步骤：明确记录驱动与主键/组合键契约，同一记录的多个list格共享稳定主键；数字和字符串类型保持。缺失或重复主键阻断需要实例身份的编辑/发布，不用字段文字或行号兜底。身份唯一性独立于显示值和输入顺序校验。

关闭标准：CER-09唯一键数为2，CER-10明确错误；同值明细中的单格覆盖、排序、删除插入和局部取消不互相污染。

### CER-F06：局部重复与几何尚不完整，并存在静默覆盖

**P1。CER-11/12/13失败。**

三个反例：

- 固定说明放在第二条数据将占用的位置，被cellsMap.set直接覆盖，编译仍valid=true。
- 声明parents.row=team的组内静态“本组汇总”在两个组中只出现一次；所有literal先被当固定内容放置，没有跟随上下文重复。
- 两个并排根数据块在模板中同起始行，第二块被currentRowCursor整体接到第一块之后，原设计起始位置没有保留。

新模型仍没有足以表达原型块、跟随锚点、组尾位置和局部空结果策略的完整协议/UI。推导直接父格的最小/最大坐标不等同已完成方案中的块图与几何约束求解。

整改步骤：补显式局部原型、重复归属和固定/跟随定位；先测量子块再按约束摆放，独立并排块各保留锚点；静态内容可明确属于重复块；写入前用占用索引检查碰撞，禁止无诊断覆盖。不能通过让所有静态文字都重复来修复，标题必须仍可固定。

关闭标准：三个反例通过，并补组尾、不同高度子块、同页横/纵混排及碰撞诊断的真实配置用例。

### CER-F07：多区域共用第一个过滤，后续数据表按静态发布

**P1。CER-14/15失败。**

同一数据源两个区域，r1过滤A、r2过滤B；r2独立SUM本应20，实际为10。新引擎先读取doc.regions[0]并对全部工作表格使用其filteredRecords和analysisId，允许多区域的validator没有对应执行隔离。

第二工作表中SUM(qty)应30，实际为null。compileCellReport只对默认plan工作表做数据展开，后面的工作表仍进入仅处理literal的静态分支。不能用“第二张静态表已支持”替代“第二张数据表已支持”。

整改步骤：逐sheet/region编译各自数据上下文、过滤、实例身份与版本戳，再进行同页位置组合与碰撞检查；多数据源使用明确的数据集映射，不能把一个rawDataset静默用于所有来源。后续工作表也走真实数据引擎。能力未接通前明确阻断对应结构，不返回看似有效的错数。

关闭标准：r2为20、第二表为30；跨区域同名成员的覆盖/取消互不命中，dataRevisions涵盖实际使用的数据集。

### CER-F08：新路径遗漏条件格式和现有number格式

**P2。CER-16/20失败。**

quantity>15的红色条件规则在B=20的格没有生效；新引擎只处理部分template-cell styleRules，没有执行conditionalRules。当前侧栏可选format=number，1234却发布为"1234"，没有预期"1,234.00"；新formatValue只处理另一组格式名。

整改步骤：统一新旧路径格式映射与规则求值，保留模板基础样式并只覆盖显式属性，条件样式使用正确当前值；支持的sheet/region/template-cell作用域一致。合并求值应看到最终样式边界，避免同值合并掩盖不同背景。

关闭标准：CER-16/20通过，预览与VTable文本/背景一致，null不被当0、取消bold不丢失、非目标格不扩散。

### CER-F09：生成合并仍被固化，原生取消快照不产生规则意图

**P1。CER-17/21失败；CER-18为范围内正向对照。**

开启team分组覆盖，实际生成2个成员合并。没有修改预览，直接同步快照后，layoutRules从0变成2条人工范围，动态结果被误当源规则。反向把工作簿mergeData设为空，模拟取消后的实际快照，保存并重编译后仍生成2个merge，因为原策略enabled和suppression均未改变。

这些用例验证真实同步/保存边界，不冒充本轮已经在浏览器点了原生取消按钮。源码事件桥接也没有完整的合并/取消语义事务，所以仅保存空merge数组无法表达用户意图。

手动设置enabled=false的简单用例CER-18可以取消成功，说明resolver部分配置分支可用；缺口在命令、快照与源规则之间，不能宣称所有取消都失效，也不能用直接写enabled证明原生操作闭环。

整改步骤：

1. 保留生成merge的owner/origin和当前版本索引，未发生合并编辑时不得把它们写入LayoutRule。
2. 原生取消在命令边界转为关闭整条策略或成员/实例抑制，带稳定ruleId、完整业务上下文及范围；空快照只描述当前投影，不能替代取消意图。
3. 模式切换/保存/数据刷新共用提交事务，旧grid不能解释新数据坐标；设计态空bindings保留源规则。
4. 分组footprint使用完整祖先路径，取消记录按policyId隔离；本轮未穷尽其他policy交叉，需补例外边界测试。

关闭标准：CER-17源人工规则仍为0；CER-21保存/重编译无合并；真实原界面执行取消、切设计/预览、保存重开、新增成员/指标和排序后均符合明确作用范围。

## 5. 为什么现有CE22通过仍不能关闭方案

原设计的CE编号与当前实现测试的实际断言存在范围差异：

| 编号 | 设计要求 | 当前测试实际覆盖 |
| --- | --- | --- |
| CE-T11 | 组内小计、块后总计、固定标题和旁边摘要的scope及定位 | 静态标题与一个独立全量汇总，不验证组尾/跟随 |
| CE-T15 | 新增指标/明细、成员移除回归后取消仍保留 | 构造初始suppression后检查两个当前范围，没有完成数据变化往返 |
| CE-T17 | 无主键、独立列表粒度不一致、跨源关系诊断 | 被改成单区域过滤检查，不等价于原需求 |
| CE-T19 | 真实迁移、重复迁移和reader降级保护 | 分别编译旧/新文档，不能证明迁移及降级保护 |
| CE-T20 | 真实原应用配置/移动/保存/重开/热更新 | 调用compileCellReport检查发布对象，没有浏览器或宿主保存 |
| CE-T22 | 大数据、轴乘积和深层重复上限 | 500条事实生成120格的基础检查，没有展开上限或深层边界 |

建议保留已有有用的22项测试，使用清楚的覆盖说明；为原设计未执行的操作另补用例及证据，不通过重命名编号把范围缩小后标记全部闭环。

## 6. 整改顺序与下轮关闭标准

1. 先统一v2绑定身份/保存消费、公式和碰撞保护，防止把入口接通后直接向用户暴露丢值和错数。
2. 补时间分桶、明细主键、多区域/数据表隔离；暂不支持的能力明确限制并诊断。
3. 完成块图、固定/跟随内容及几何求解，再把新建默认入口和版本化保存切到v2；兼容旧报表入口保持。
4. 打通原生合并/取消事务与来源隔离，保留局部例外，统一样式/格式执行。
5. 重跑CER21、原213单测、FR12/RC25/AC-CX15及按变更必要的专项；新增浏览器主流程证据，不能只重新运行当前22项宣布完成。

每项关闭须核对目标值、非目标值、实例身份、源规则、诊断、publication和VTable适配；涉及UI的发现还需真实入口操作。新设计要求的自由布局与混排目前不能整体关闭。错误编译结果没有保存到真实看板，本轮事实数据保持不变。
