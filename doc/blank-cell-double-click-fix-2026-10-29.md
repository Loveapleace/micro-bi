# 空白单元格双击编辑修复

日期：2026-10-29。对应整改记录第56节。界面保持第54节版本，本次仅修复编辑事件分流。

后续补充：生成表头/指标标签也允许双击原生改文案，属于下表“已有内容”的例外，按[第57节约定](generated-label-editing-implementation-and-acceptance-2026-10-29.md)执行。

## 原因

原事件桥接在收到双击后先无条件取消Univer原生编辑，再调用业务回调。业务回调发现空白格不能打开高级配置便直接返回，造成“高级配置没打开，原生输入也被取消”。

独立浏览器在A2复现：`BeforeSheetEditStart`的eventType为3、cancel为true，未触发`SheetEditStarted`。该拦截在第54节及更早的事件代码中已存在。

“空白格不弹高级配置”与“空白格不能直接编辑”是不同要求。正确行为如下：

| 场景 | 双击行为 |
| --- | --- |
| 模板设计态、数据区外空白格 | 进入Univer原生编辑，可录入静态文字或公式 |
| 模板设计态、已有有效内容或绑定 | 打开该角色的高级配置 |
| 模板设计态、数据区内空隙 | 保持保护，通过左侧面板配置数据结构 |
| 动态预览态 | 保持只读 |
| 数据区外F2及字符输入 | 保留原生输入行为 |

## 修复

- `univerEvents.ts`的双击业务回调明确返回boolean：true表示业务已接管，才取消原生编辑；false表示将空白格交给原生输入。已有取消标记不会被反向清除。
- `HybridCellDesigner.tsx`分别处理有效配置对象、受保护空隙和可编辑空白格；不再把“没有高级配置对象”当作双击已经处理。
- `guidedEditing.ts`在预览态先执行只读保护，再处理设计态的双击例外；没有因为放开静态空白格而放开数据区或预览。
- 双击判定由两处共用同一函数，覆盖数字事件类型、字符串类型和inputEvent形态；F2/字符输入不进入高级配置分支。
